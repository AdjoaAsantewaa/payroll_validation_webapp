# Exited Employee Guidance

## What triggers this issue

An employee's record in the employee master data is marked exited once
they leave the organisation, along with the date they left. If a payroll
row references a Staff ID that belongs to an exited employee, it is
flagged, because that person should generally no longer be receiving pay.

## The default assumption

Payroll should not continue for someone who has left. Unless there is a
specific, legitimate reason, an exited employee appearing in a current
payroll file is treated as a mistake -- most often the row was carried over
from a previous cycle's file rather than removed.

## When a payment may genuinely still be due

There are limited legitimate cases: a final payment that was processed
after the formal exit date, an adjustment or correction relating to a
period before the employee left, or a similar one-off situation. In these
cases the row is not automatically wrong, but it does need a specific
explanation before the Payroll Specialist can approve it.

## What the submitter should do

If the employee should not be included in this payroll period, remove the
row from the file and resubmit. If a payment is genuinely still due,
provide a clear explanation of why -- for example, referencing the specific
final payment or adjustment -- so the Payroll Specialist has enough
information to review it.

## What the Payroll Specialist should do

Treat an exited employee as high priority. If no explanation is given,
query the department directly rather than approving or rejecting on
assumption. If an explanation is given, check that it plausibly accounts
for a payment after the exit date before accepting it.
