# Payroll Submission Policy

## Purpose

This policy sets out how each department submits payroll data for a cycle,
what counts as a valid submission, and how the cut-off date is applied.

## Submission cycle

Payroll runs on a monthly cycle. Each cycle has a label (for example
"August 2026") and a cut-off date, after which the Payroll Specialist begins
final review and export. Departments should aim to submit well before the
cut-off so there is time to resolve any issues.

## What a submission contains

A submission is a single spreadsheet (CSV or Excel) covering every employee
in the department who should be paid for that cycle. Each row must resolve
to a specific employee via their Staff ID, with overtime hours, basic pay,
and allowances for the period.

## One current version per cycle

A department may upload more than once in a cycle. Each new upload
supersedes the previous one as the current version for that cycle -- the
older version is kept as history but is no longer counted in any review or
approval. Only the current version is reviewed, queried, or approved.

## Submitting with unresolved issues

A submitter is not required to have a perfectly clean file before
submitting. If issues remain after upload, the submission still goes to the
Payroll Specialist for review, and the submitter can add a note explaining
anything they were unable to resolve themselves.

## Cut-off date

Corrections and resubmissions should be completed before the cycle's
cut-off date wherever possible. If a specific cut-off is not available for
the current cycle, submitters should still aim to respond to any queries
promptly, since a late response risks the department's payroll being
delayed to the following cycle.
